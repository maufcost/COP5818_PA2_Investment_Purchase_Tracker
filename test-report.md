## Connection loss after a server commit

Check 9 shows the clear-cut case, where the server is down before the request. A connection can also fail *after* the server has run the `INSERT` but before the 201 response reaches the browser. The browser then sees the same network error and cannot know whether the purchase was saved. The app does not claim exactly-once behavior. The error message tells the user to reload and inspect the history before retrying, because a blind retry could create a duplicate, since repeated names are allowed as separate purchases.
